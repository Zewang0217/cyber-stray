## 仍须保留的上线边界

1. 线上 HTTPS、备案、证书、Casdoor redirectUris 与真实登录/推送验收须按 [部署说明](../../deploy/README.md) 同窗口执行。本次代码通过不等于线上已经完成切换。
2. SaaS 浏览器暂未重开；恢复前需可验证的网络隔离。Bun 不能带 HTTP_PROXY / HTTPS_PROXY / ALL_PROXY 启动，NO_PROXY 不豁免。
3. 旧历史同时缺 contentId 和渠道 ID 的记录仍不能反馈，本次未擅自回填用户文件。
4. 平台日预算是派发前护栏，已派发的一轮可能超过剩余额度，不是实时精确扣费。供应商在返回用量前中断产生的实际账单，需要对账；生图/视觉成本为已登记估计口径。
5. 记账故障不自动恢复。核对并补齐账本后，管理员才可清理 usage-accounting-block.json、重启 CP、恢复宠物；操作现有数据需另行授权。
6. 当前仍为单实例调度；留存、内容质量、真实并发容量和长期每用户成本，需要邀请内测验证。

## 提交前 subagent 复审补充

三个 subagent 按运行时、安全部署、控制面及用户路径复审，发现并修复以下遗漏，随后完成对应红绿回归及全包验证：

- 首页邀请链接经过未登录中间件时丢失令牌。现在仅将共享契约认可的邀请令牌透传到本站认证入口；已有链接继续可用。Web 消费方与 CP 邀请生成接口分别验证，保持 Web 镜像独立构建。
- 已完成游荡后的反思失败会丢掉数值回报及推送事件。现在保留完成结果、发布明确反思失败事件，并跨重启记录欠下的反思；后续先重试反思，记账异常仍持久暂停。
- Web 健康探针访问首页时进入 OIDC，导致首次 HTTPS 启动循环依赖。现在探测公开登录页且拒绝重定向。
- 生图/视觉提供方已返回成功，但解析或落图失败时漏记量。agent 与 CP 均在成功 HTTP 响应后先计量，再解析/落图；CP 记录请求时的模型快照，避免热更新造成错价。
- 总 token 存在时允许单侧拆分，可能把另一侧当零。共享 schema 现拒绝半拆分及总量不一致，保留只有总量的历史记录兼容。

最终复审范围内没有未解决的代码发布阻断。业务上线前置条件仍需单独满足。

用户已确认域名备案尚未通过：本次只合并 develop，创建待发布 main PR，不合并 main、不触发生产部署。生产基线检查显示 HTTP 登录及 OIDC discovery 可达，三个 HTTPS 域名均返回 521，服务器无对应 TLS 证书，仓库 APP_URL 尚未配置。线上仍为旧版本，不能把本地修复验证记作线上验收成功。
