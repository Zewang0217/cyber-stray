# PRD — 宠物 IP 自定义 + 性格系统 + 作息/日记/梦境 + 表情包系统

> 来源:grill-with-docs 会话(2026-08-19)+ MemeResearch 行业调研。决策记录:ADR-0001(内容生成管线)、ADR-0002(宠物作息)。领域词汇见 CONTEXT.md。

## Problem Statement

赛博宠物现在的形象是**平台预置的单一角色**,主人无法拥有"属于自己的宠物";宠物每天游荡、推送,但**不留痕迹**(没有日记、没有梦境,宠物像没有"生活"的工具);宠物和主人的互动**没有情绪颗粒度**(没有性格,所有宠物行为参数一样、说话一个语气);推送内容**只有文字**(没有表情包这种现代聊天语言,错失"宠物会做表情包"的差异化)。

主人要的是"我的宠物是活的":形象是我的、它有自己的性格、晚上会睡觉做梦、会把一天写成日记、会给我做表情包。

## Solution

1. **宠物 IP 自定义**:免费用户用平台预置 IP 系列(即开即用);Pro/BYOK 用户输入 spec(纯文本+选项)→ 平台全自动跑管线(概念图 → 用户确认 → 参考图锁角色 → 单图多状态生成 → 切分 → 两层质检)→ 交付一套专属宠物形象,租户私有,web 端按租户加载,无自定义回退内置素材。
2. **性格系统**:认领宠物时选性格(可拓展注册表:好奇/活泼/慵懒/沉稳…,每性格独特优劣),影响行为参数(无聊/精力速率、游荡效果、探索倾向)、说话语气、日记/梦境风格;前端展示性格。
3. **真实作息 + 日记 + 梦境**:用户可设宠物睡眠时间段;睡眠期宠物不游荡,夜间访问看到睡觉状态 + 查看当晚梦境(睡前预生成抽象叙事);独立日记页,每天一篇性格化日记(睡前生成,多风格选项,可定时推送);睡眠期轻互动(拍拍会哼唧但不醒,梦境不打断)。
4. **表情包系统**:两个触发点——日记写完生成(日记配图/相关梗)、推送后 agent 自主调 tool 生成(觉得话题适合就做);图文分离(生图只画画面,梗文字程序叠加);推送补发带图;表情包图鉴自动收录过质检的,带元数据(话题/情绪/日期),支持下载/删除。

## User Stories

### 宠物 IP 自定义
1. As a 免费用户, I want 开箱就有平台预置的宠物形象, so that 我不需要任何操作就能拥有一个好看的宠物。
2. As a Pro/BYOK 用户, I want 用文字+选项描述我想要的宠物(可抽象/自由风格), so that 我能得到一个独一无二的形象。
3. As a Pro/BYOK 用户, I want 提交 spec 后看到一张角色概念图并确认/提出调整, so that 最终形象符合我的想象而不是一次性赌运气。
4. As a Pro/BYOK 用户, I want 不满意时调整 spec 重新生成概念图, so that 我可以迭代到满意为止。
5. As a Pro/BYOK 用户, I want 确认后的形象自动生成全套状态(多状态动画素材), so that 宠物在走路/睡觉/开心时都是我选的那个形象。
6. As a Pro/BYOK 用户, I want 生成的 IP 只有我自己能用, so that 我的宠物是私有的。
7. As a Pro/BYOK 用户, I want 知道我的生成配额还剩多少, so that 我规划使用。
8. As a Pro/BYOK 用户, I want 生成失败(质检不过)时收到明确反馈并可以改 spec 重来, so that 我不会面对一个坏的成品。
9. As a 主人, I want web 端宠物动画使用我的自定义形象, so that 我和宠物互动的每一步都是"我的宠物"。

### 性格系统
10. As a 主人, I want 认领宠物时从几种性格中选择, so that 我的宠物从出生就有个性。
11. As a 主人, I want 每种性格有清晰的差异说明(优劣/特点), so that 我能做出有意义的选择。
12. As a 主人, I want 前端展示宠物的性格, so that 宠物的人格可见。
13. As a 主人, I want 性格影响游荡节奏(无聊增速/精力恢复/游荡效果), so that 好奇的宠物真的更爱逛、慵懒的真的更懒。
14. As a 主人, I want 性格影响探索倾向(新话题 vs 熟话题), so that 好奇的宠物总发现新东西、慵懒的窝在熟悉领域。
15. As a 主人, I want 性格影响宠物说话语气, so that 推送/互动读起来是"这个性格"在说话。
16. As a 主人, I want 性格影响日记/梦境风格, so that 日记读起来是这个宠物写的。
17. As a 平台, I want 性格做成可拓展注册表, so that 后续加新性格不用改核心逻辑。

### 作息 / 梦境 / 日记
18. As a 主人, I want 设置宠物的睡眠时间段, so that 宠物按我的生活习惯作息。
19. As a 主人, I want 睡眠期宠物真的不游荡, so that 作息是真实的不是装饰。
20. As a 主人, I want 夜间访问看到宠物在睡觉(睡觉动画), so that 有"它睡了"的活物感。
21. As a 主人, I want 夜间访问可以查看当晚梦境(抽象叙事), so that 我能看到宠物梦到了什么。
22. As a 主人, I want 睡眠期轻互动(拍拍/说话)宠物会哼唧回应但不醒, so that 互动不打断梦境也不破坏作息。
23. As a 主人, I want 独立的日记页面/tab, so that 我随时回看宠物每天的生活。
24. As a 主人, I want 日记记录当天的游荡足迹、新发现、与我的互动, so that 日记是真实的生活记录不是编的。
25. As a 主人, I want 日记用宠物的性格化语气写作, so that 每篇日记都像宠物亲手写的。
26. As a 主人, I want 日记可选写作风格(随意/认真/文艺等), so that 我控制日记的调性。
27. As a 主人, I want 定时推送日记(可配置), so that 睡前/早上自动收到"今天的日记写好了"。

### 表情包系统
28. As a 主人, I want 宠物在日记写完后生成一张相关表情包, so that 日记不只文字还有梗。
29. As a 主人, I want 宠物在推送后自主判断话题适合做表情包就生成, so that 宠物会主动给我做表情包(差异化)。
30. As a 主人, I want 推送消息附带生成的表情包图片(飞书/TG 原生图片), so that 表情包随互动自然送达。
31. As a 主人, I want 表情包有"抽象梗图"和"我的宠物形象"两种, so that 既有通用梗也有专属宠物梗。
32. As a 主人, I want 表情包梗文字清晰可读, so that 不会出现 AI 画糊文字的尴尬。
33. As a 主人, I want 表情包图鉴页自动收录所有过质检的表情包, so that 我随时翻宠物做过的表情包。
34. As a 主人, I want 图鉴按时间/话题筛选,每张标注话题/情绪/日期, so that 我能找到想要的那张。
35. As a 主人, I want 图鉴支持下载/删除, so that 我可以保存喜欢的、清理不喜欢的。
36. As a 平台, I want 表情包生成受配额/成本控制, so that 生图成本不会失控。

## Implementation Decisions

### 生图管线(共用,ADR-0001)
- **图文分离**:生图只画画面,梗文字由 LLM 出文案 + 程序叠加(PIL/Canvas),绝不让模型画整句中文(行业调研结论,qwen-image 官方明示长文本不准)。
- **参考图锁角色**:角色概念图是唯一角色锚点;多状态生成与 IP 表情包都用 qwen-image 图生图参考模式复用概念图,不训 LoRA。
- **单图多状态**:首选一张图多状态(九宫格 9 状态 / 四宫格 2x2×3 张)程序切分;每状态 1 帧静态 256px 透明 PNG + manifest;动画感由播放器程序微动画补(idle 呼吸/walk 位移/celebrate 弹跳)。**spike(issue 1)实测选优**,失败回退逐状态生成(现有 pet-sheet 保底)。
- **两层质检**:结构层(脚本:帧数/透明底/内容占比)+ 语义层(qwen-vl:状态正确/角色一致/无文字水印/无畸形);失败单状态重试,N 次不过 → 返回用户改 spec。

### 存储与交付(租户私有)
- 成品落 `data/tenants/<sub>/pet-assets/`(与记忆同根,备份天然包含);CP 加鉴权静态路由服务(session claim 校验租户,他租户 404);web 按租户 manifest 加载,无自定义回退内置素材。web 保持只读契约。

### 性格系统(本期实现,可拓展注册表)
- 认领时选择;注册表 = 每性格一组 {独特优劣描述, 行为参数倍率(boredomPerMinute/energyPerMinute), 游荡效果偏移, 探索倾向(新/旧话题权重), 语气 prompt 段, 日记/梦境风格模板}。
- 参数映射在 propagate 层按性格解析(现有 PropagationRates 派生);探索倾向在 agent 游荡话题选择处注入;语气在 system prompt 注入。前端认领页 + 宠物页展示性格。

### 作息 + 睡前任务(ADR-0002)
- pets 表加 sleepStart/sleepEnd(本地小时 0-23,可空 = 无作息,同 pushWindow 字段模式);scheduler isReady 增加睡眠期检查(睡眠中不拉 worker)。
- **睡前任务** = 新 worker 模式(非游荡):睡眠开始触发,一次生成当晚三样——当天日记(足迹/新兴趣/主人互动,性格化叙述,多风格选项)、当晚梦境(兴趣抽象联想叙事,存独立文件)、日记表情包(可选)。
- 睡眠期轻互动:拍拍 → 翻身/哼唧动画回应,不醒、梦境不打断、不改真实参数。

### 表情包系统
- agent 新工具(image-meme tool):agent 推送后自主判断调用;日记链路在睡前任务尾部触发。
- 生成 = LLM 出文案(话题→梗)+ 画面生图(抽象:通用风格 / IP:概念图参考)+ 程序叠加文字 + 质检(同管线)。
- 推送补发:飞书/TG 消息附件带图,web 推送附链接;图鉴 API 收录带元数据(话题/情绪/日期),支持下载/删除。

## Testing Decisions

- **原则**:只测外部行为(输入→输出契约),不测实现细节;LLM/视觉模型/生图 API 一律注入 mock(现有测试先例已如此)。
- **纯函数层**(先例:`propagate.test.ts` / `interest-graph.test.ts`):
  - 性格注册表 → 参数解析正确性(每性格倍率/偏移/阈值)
  - 作息判定(isReady 在睡眠期/非睡眠期/无作息默认)
  - 日记/梦境生成器(输入足迹/兴趣/反馈 → 输出 markdown 结构,性格风格差异)
  - 图文叠加器(文案+画面 → 成品,文字清晰/位置正确)
- **worker 端到端**(先例:`run-one-wander.test.ts`):睡前任务(游荡数据 → 日记/梦境/表情包文件落盘)、推送后表情包 tool 触发链。
- **spike**:九宫格 vs 四宫格为人工验证实验(真实生图 API),输出数据报告,不进自动化测试。

## Out of Scope

- 记忆巩固(openclaw 真记忆压缩)——backlog,看情况再上
- 表情包收藏/置顶——首版不做,图鉴只有下载/删除
- 睡眠期戳醒(提前醒来/梦境作废)——睡眠质量机制上后再考虑
- 多宠物——1 租户 1 宠约束不变
- LoRA/微调角色一致性——参考图方案足够,不做
- 免费用户自定义 IP——预置系列专属
- CLIP 语义检索(图鉴升级路径)——SQLite 元数据检索先行

## Further Notes

- **顺序**:issue 1 = 生图管线 spike(前置实验,结论回填本 PRD 再动其余);性格系统可独立并行;日记/梦境依赖性格(风格);表情包依赖 spike/参考图管线。
- 差异化机会(调研结论):"宠物 agent 自动生成专属表情包并收录"行业空白,无直接竞品。
- 默认作息档位、IP 生成配额具体数字(当前建议 2 套/月)、日记推送默认时段——产品细节,进 issue 时定。
- 决策详见 ADR-0001 / ADR-0002;领域词汇见 CONTEXT.md。
