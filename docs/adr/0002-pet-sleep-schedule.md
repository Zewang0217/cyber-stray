# 0002 — 宠物真实作息：睡眠期停游荡 + 睡前统一生成内容

宠物不是 24 小时在线的推送机器：有**用户可配置的睡眠时间段**（同 pushWindow 字段模式），睡眠期调度器跳过游荡；前端夜间访问展示睡觉状态。睡眠开始时刻同时触发一次"睡前任务"，统一生成当晚三样内容：**当天日记**（事实 + 性格化叙述）、**当晚梦境**（抽象叙事）、**日记表情包**（可选）。

## 动机
- 用户明确要"真实作息"：宠物晚上睡觉是活物感的一部分，不是纯展示。
- 睡前是自然的"当天总结"时刻——日记/梦境/表情包一次生成，避免三次独立调度。
- 睡眠期主人仍可轻互动（拍拍 → 翻身/哼唧动画），但不醒、不打断梦境、不改真实参数——活物感优先于 Tamagotchi 式照料逻辑。

## Considered Options
- **纯展示作息**（夜间只是前端显示睡觉，游荡照跑）：不砍夜间推送时段，但"晚上还在游荡的宠物"与"它睡着了"矛盾 → 否，用户拍板要真实作息。
- **可戳醒**（互动即醒、梦境作废）：仪式感强但有"毁掉梦境"的互动惩罚 → 暂缓，睡眠质量机制上后再考虑。
- **睡醒再生成日记**（次日醒时补写昨天）：日记延迟、梦境与睡眠期脱节 → 否，睡前生成。

## Consequences
- 调度器 isReady 增加睡眠期检查（睡眠中不拉 worker）；pets 表加 sleepStart/sleepEnd（可空 = 无作息，默认档位）。
- 睡眠期无推送——深夜推送时段牺牲，属有意取舍（作息是 Pro 可配功能，默认档位需产品定）。
- 睡前任务 = 一种新的 worker 模式（非游荡，只做总结生成），复用生成管线与质检。
- 梦境文件 `diary/dreams/YYYY-MM-DD.md` 独立于日记文件，夜间访问零延迟读取（预生成）。
