# 0010 — 推送门控重构：评分防火墙 → LLM 自判断（反馈抽样器）

推送价值门控（PushGate，Phase 5）原为评分公式 `0.4×兴趣相关度 + 0.4×用户偏好 + 0.2×内容质量 ≥ 阈值 0.5`。生产实证（issue #147）暴露三个致命缺陷：①兴趣相关度公式倒挂——`matchedWeight/totalWeight` 让命中头号兴趣的内容只得 0.29 分，比冷启动中性分 0.5 还低，单兴趣内容数学上永远过不了门；②单条 dislike 直接写死整个话题（"天文"进 dislikes → 所有天文内容被拦）；③评分只拦"到达主人"，把宠物探索内容也拦了，阻塞兴趣图谱演化。

## 决策

**1. 门控从"评分防火墙"改为"反馈抽样器"**：不再有评分公式与阈值。speak 由 LLM 在 ReAct 循环内自判断是否调用（可保持沉默），判断依据 = prompt 注入的双图谱上下文 + 剩余日预算 + 分享准则。

**2. 防骚扰职责移交**：S11 日预算（会员等级 + 用户设置决定）+ 工具层护栏（去重/每游荡上限）。话痨可接受，不靠内容评分压制。

**3. 双图谱上下文（ADR-0011）**：用户兴趣图谱（主人想看什么）+ 宠物好奇图谱（宠物想探索什么）共同进 prompt，LLM 权衡相关性 vs 新奇度；"小惊喜" = 好奇图谱的探索性话题。

**4. 可观测**：LLM 每次 speak 输出 reason 落盘（gateReasons 语义保留），dashboard 展示"为什么推这条"；被预算/护栏拦下的记录标 planLimited（不丢）。

## Considered Options
- **评分公式修复 vs 纯 LLM 自判断**：公式修复（匹配权重归一化）可解倒挂，但无法解决"单条反馈写死话题"与"探索被拦"两个结构问题；LLM 自判断把"相关性/新奇度"权衡交给模型在具体内容语境里做，公式降级为辅助上下文。代价是失去确定性（相同内容可能这次推下次不推），靠 reason 落盘保可观测 → 选 LLM 自判断。
- **独立判断调用 vs 内联进 ReAct**：speak 前单独调一次 LLM 输出 `{share, reason}` 是自确认（同一模型生成又验证，无第二意见价值）且每次 +1 调用；内联零额外成本、最自然（OpenClaw heartbeat NO_REPLY 模式）→ 内联。
- **代码探索槽 vs prompt 引导**：见 ADR-0011 决策 4（先 prompt 引导，B 后备）。

## Consequences
- quality hook 重写：不再 evaluate/deny，改为注入判断上下文 + 记录 reason + 护栏（去重/上限/预算）。
- react.ts prompt 重构：双图谱上下文 + 剩余预算注入；配合 prompt cache 优化（固定段前置、动态段后置，issue 待办）。
- speak 记录 schema 扩展：explore 标记（若后续加探索槽）、reason。
- 原有 PushGate 评分引擎、阈值校准、内容扫描代码删除或归档（校准在 SaaS 短命 worker 下本就无效）。
