# 0001 — 内容生成管线契约：图文分离 + 参考图锁角色 + 静态帧

宠物 IP 自定义与表情包系统共用一条 AI 生图管线。三个决策锁定：

**1. 图文分离**：生图只画画面，梗文字由 LLM 出文案 + 程序叠加（PIL/Canvas），绝不让模型把整句中文画进图里。调研确认这是行业压倒性主流（Supermeme.ai / Imgflip API / Memethropic 全部是"caption + 画面 + 代码叠字"）；qwen-image 官方文档明示长文本逐字准确性有限，Glyph-ByT5 论文测 SDXL 画字基线 <20% 准确率。未来若遇画字能力飞跃（如 Seedream 4.0 级别中文渲染），可对短标题开白名单，但整句梗文字永远程序叠加。

**2. 参考图锁角色**：一切"同一个形象"的一致性靠图生图参考模式（qwen-image 参考图输入），不训 LoRA/微调。用户确认后的角色概念图是唯一角色锚点，多状态生成、IP 表情包批量生成都复用它。行业同路：Seedream 4.0 支持 10+ 参考图、MyGIF 1 张。

**3. 单图多状态 + 静态帧**：首选"一张图多状态 + 程序切分"（九宫格 9 状态一次，或四宫格 2x2×3 张，spike 实测选优），每状态 1 帧静态图，动画感由播放器程序微动画补（idle 呼吸/walk 位移/celebrate 弹跳）。放弃早期"每状态 3 帧动画帧条"方案——27 格网格每格分辨率不足，与"AI 质量要保证"冲突。

## Considered Options
- **AI 画文字 vs 图文分离**：AI 画文字风格更"原生"但中文错字率高（<20% 基线）→ 否。
- **逐状态生成 vs 单图多状态**：逐状态（现有 pet-sheet 流程）一致性强但生成次数多、成本高；单图多状态省成本但每格分辨率低 → 单图为先，spike 后按清晰度/成本数据定；逐状态保留为回退路径。
- **LoRA 微调 vs 参考图**：LoRA 一致性最强但要训练数据 + 每形象训练成本，2C4G 服务器跑不动 → 否。

## Consequences
- 素材契约：每状态 1 帧 256px 透明 PNG + manifest JSON，落 `data/tenants/<sub>/pet-assets/`；播放器需加程序微动画参数（框架已定：JS 帧驱动）。
- 两层质检（结构 + qwen-vl 语义）是全自动流程的质量关，单状态失败重试而非整组推倒。
- 文字层独立 = 文案可二次编辑/换字体/多语言，图鉴元数据（话题/情绪）可挂文字层。
