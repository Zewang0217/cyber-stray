<objective>
给记忆系统的 manage 半边打地基的第一块砖：在 Markdown 真相源之上加可查询 JSON 索引（`data/memory/.index.json`），消除检索/反思的 O(N) 全文件扫描与 `getMemory` 读即写的写放大。落实 **MEM-01** + D-09 错误显式化红线（not found 返 null / 解析失败抛错）。

这是 MVP 垂直切片的第一刀：一条从"写入 → 索引 → 检索"的端到端能力，让记忆系统在不破坏现有调用方签名的前提下，内部改走索引层。

**Purpose:** 为 Phase 4 反思回路与 Phase 2 兴趣图谱提供高效检索前提；为 MEM-02 的 consolidator（依赖 store.saveMemory 双写路径）铺路。
**Output:** `MemoryIndex` 类（JSON sidecar CRUD + 原子写 + 启动重建）、types.ts schema 扩展、MemoryStore 改造（getMemory/getRecentMemories/saveMemory/deleteMemory/readIndex）、Wave 0 测试。
</objective>
